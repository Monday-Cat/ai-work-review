# 参考文件：组件命令（解析 / 查 / 登记 / 影响 / 比对）

组件卡与页面卡模板、布局草图标记语法、五条子命令细则的正本。单源：改细则只改本文件，改完按「技能正本规则」同步项目副本。

## 模板：组件卡

`docs/组件文档/<分类>/<组件名>.md`，一个组件一张卡；`docs/组件文档/_索引.md` 总览：

```markdown
# 组件：<名称>

- **路径**：（源码文件位置，如 lib/shared/widgets/xxx.dart）
- **分类**：（基础组件 / 业务组件）
- **标签**：#能力/xx #能力/yy #场景/zz（从 `_标签.md` 受控词表取；没有合适的先提议）
- **职责**：（什么场景用它，一句话）
- **布局**：（代码块内 ASCII 草图或「无内部布局」，画法见下方说明）
- **参数 / API**：（关键 props / 回调 / 参数表）
- **示例**：（最小用法片段）
- **不要用的场景**：（可选：边界与替代）
- **使用方**：（哪些模块 / 页面在用；以 `组件影响` 的代码反查为准，卡上的过期条目由它纠正）
```

**标签治理**（同概念卡）：`docs/组件文档/_标签.md` 是受控词表，登记两维标签的合法值——**能力**（干什么：输入 / 选择 / 倒计时 / 金额键盘 / 弹层 / 加载…）与**场景**（用在哪：表单页 / 列表行 / 深色 / 全屏…）。作者定标签；AI 打标只能从表里取，需要新标签时提议、确认后入表。词表不存在时，首次 `组件解析` 拟一版初稿请作者确认再打标。标签用 Obsidian 原生层级标签（`#能力/输入`），可全局搜索。

**布局草图**：读组件的 build / Widget 树（iOS 为布局代码），画**区域级 ASCII 草图**——代码块内用 `┌─┐│└┘` 框出大致分区与子元素位置，不抠像素；占位 / 间距 / 行分布用「布局草图标记」标注（语法见下节）。例如：

````
```
┌────────────────────────────────┐
│ 标题<max><center>       [关闭] │
│ <v12>                          │
│ 金额输入                        │
│ <between> [取消]     [确认<max>] │
└────────────────────────────────┘
默认：v16 h8
```
````

单一控件没有内部布局的，写「无内部布局」。结构画大致示意即可，**标记必须与代码一致**；改了组件布局要同步重画。

## 布局草图标记

页面卡与组件卡的布局草图共用一套几何标记。原则：**形状给人看，标记给 AI**——框线宽窄潦草无妨，标记是几何真值；AI 重建布局只读「行结构＋标记」，不依赖框线比例。**默认语法以本节为准**；项目要覆盖（如非 Flutter 的映射表）时在 `docs/公用配置/` 落 `布局标记` 概念卡，卡优先。

- **占位**（缀在编号或格内内容后）：`<full>` 占整行；`<50%>` `<25%>` 行内占比（同行各块百分比之和为 100%）；`<max>` 吃掉同行剩余宽度。独占一行的块默认通栏，不标。
- **间距**（写在两块之间）：`<v10>` 纵向间距 10、`<h10>` 横向间距 10；每张卡在草图下方声明一次**默认间距**（取项目设计系统），只标例外。
- **行分布**（写在行首，约束整行）：`<right>` 靠右、`<center>` 居中、`<between>` 首尾贴边中间均分（Flutter `spaceBetween`）、`<evenly>` 含两端等间距均分（`spaceEvenly`）；靠左默认不标。
- **同行多块**用 `│` 分格；**标记可叠加**：`②<max><center>`＝吃剩余宽且内容居中。
- **子行**（行首 `└`）：本行不是新的整行，是上一行**某格内部的下一行**（如「图标｜名称列两行｜右侧值」的头部形态）。默认挂上一行带 `<max>`/占比的主格，归属有歧义时写 `└(格n)` 指定；`└` 行内可再用 `│` 分格与标记，作用于格内。**缩进只作示意，不按列位解读**——归属看 `└`，不看空格。
- **行＝Column 的 child**：草图自上而下每行＝Column 的一个子块，顺序即声明顺序；带 `│` 分格的行＝Row。行首分布标记按主轴读：多块行＝Row 横向分布（`<between>`/`<evenly>`…）；单块行＝该块在 Column 里的横向对齐（`<center>`/`<right>`）。
- **单块行宽度**：不标＝通栏（横向占满）；`<center>`/`<right>`＝**按内容宽**并居中/靠右（如 240 宽按钮居中：`<center> ④`）；通栏但内容居中写 `<full><center>`。注意此默认**故意≠Flutter Column 默认**（Flutter crossAxisAlignment 默认 center），不写死这条 AI 会按 Flutter 默认重建、整页跑偏。
- **纵向撑满**：块吃掉 Column 剩余高度（Flutter `Expanded`）标 `<vmax>`；滚动主体（ListView 等）不标，画到框底即可。
- **分层**：页面卡只画槽位层；组件内部几何画在组件卡布局图里，两层同一套语法。
- **校验**：出现上述之外的标记＝非法标记，属报告项（`文档检查` / `组件比对`）。

示例（读法：① 固定宽靠左，② 吃剩余宽内容居中，③④ 靠右横距 8，⑤行两块各半，⑦行首尾贴边，⑨行靠右）：

````
```
┌──────────────────────────────────┐
│ ①    ②<max><center>   ③ <h8> ④ │
├──────────────┬───────────────────┤
│ ⑤<50%>       │ ⑥<50%>            │
├──────────────────────────────────┤
│ <between> ⑦                    ⑧ │
├──────────────────────────────────┤
│ <right> ⑨                        │
└──────────────────────────────────┘
默认：v16 h8
```
````

## 模板：页面卡

`docs/页面文档/<模块>/<页面名>.md`，一个页面一张卡；`docs/页面文档/_索引.md` 总览（按模块分组：页面、路径、业务双链）。页面卡是**索引层**：只画槽位、只链接组件，不复制组件内部布局——画两份必漂移。

```markdown
# 页面：<页面类名>

- **路径**：（页面文件位置，如 lib/features/finance/presentation/pages/amount_page.dart）
- **模块**：<模块名>
- **业务**：（双链到描述本页面的业务线文档，如 [[2026-09-01-金额输入]]；没有对应业务文档写「无」）

## 布局

┌──────────────────────────┐
│ ①<max>             ②    │
├──────────────────────────┤
│ ③                        │
├──────────────────────────┤
│ <between> ④        ⑤    │
└──────────────────────────┘
默认：v16 h8

| 编号 | 位置 | 作用 | 组件 |
|---|---|---|---|
| ① | 顶部左侧 | 标题＋返回 | —（系统 AppBar） |
| ② | 右上 | 筛选入口 | filter_button.dart |
| ③ | 中部主体 | 金额输入 | [[AmountKeyboard]] |
| ④ | 底部左侧 | 实时汇总 | —（主色文本，实时刷新） |
| ⑤ | 底部右侧 | 提交 | [[PrimaryButton]] |
```

**编号＋图例**：框内放 ①②③ 编号和 ASCII 标记（`<50%>`、`<between>` 这类纯 ASCII 不破对齐），说明全放图例——每行四要素：编号｜位置（顶部通栏 / 吸底 / 右下悬浮 / 第 n 行…页面语汇）｜作用｜组件。几何真值在标记，画法见「布局草图标记」；默认间距在草图下方声明一次，图例不重复数值。
**组件列三态**：已入册写 `[[卡名]]`；代码里有、没入册写文件名（`组件登记` 入册后补链）；一次性自绘写 `—（一两句样式短语）`。样式短语守草图纪律：说清长什么样、干什么即可，细节以代码为准。
**抽组件信号**：一张卡里 `—（自绘）` 槽位越多、样式描述越长，越该抽组件——槽位复杂到想画它的内部结构，就是建组件卡或生成「组件抽取」需求的时机。
**保鲜**：`组件解析` 建卡；`组件影响` 命中页面时交叉核对图例、缺卡顺带补；`交付` 触及页面布局时重画；`整合` 织链保证业务文档↔页面卡双向双链。


## 组件 \<解析|查|登记|影响|比对\>

维护组件注册表 `docs/组件文档/` 与页面布局索引 `docs/页面文档/`：让 AI 写 UI 前知道已有什么可复用、页面长什么样，不重复造轮子。组件命令不直接改业务代码。

**组件解析 [模块]**——扫描建库：

1. 范围：点名模块只扫它的组件目录与页面目录（Flutter `presentation/widgets/` 与 `presentation/pages/`；iOS 为 View 目录与页面类所在目录）；无参数 = 全部模块＋公共组件区（Flutter `lib/shared/widgets/` 与 `lib/foundation/`；外部 UI 包只记卡不展开）。逐模块串行，上下文纪律同「深度拆解」。
2. 每个可复用组件按「模板：组件卡」建卡（标签、布局草图、职责、参数 / API、最小示例、使用方）；一次性的私有小 widget 不入册——只收职责明确、可当词用的。打标签从 `_标签.md` 受控词表取，词表不存在先拟初稿请作者确认。
3. **页面卡**：页面目录下每个页面按「模板：页面卡」建卡——读页面 build 画编号槽位草图＋四要素图例；「业务」双链从该模块业务文档里找提及本页面的业务线，找不到写「无」。已有页面卡且页面未变的跳过，不重画；`docs/页面文档/_索引.md` 按模块分组。
4. **发现功能雷同的组件**（不同模块各写了一份相似的东西）：不直接重构，生成「组件抽取」需求文档到对应模块（状态 `待审核`，走审核-开工流程）：写明雷同清单、建议的公共组件设计、迁移范围。
5. `docs/组件文档/_索引.md` **按能力标签分组**（组内每行：组件、路径、场景标签、职责短语），汇报：新入册组件 n 个、页面卡 m 张、重复嫌疑 k 组。

**组件查 \<需求描述\>**——选取推荐，**标签优先**：从需求描述提取能力 / 场景关键词 → 按标签（`#能力/…` `#场景/…`）命中缩小候选 → 读候选卡的职责与示例定夺 → 给推荐＋最小用法。没有合适的就直说没有，问作者是否新建（新建的可复用组件交付时 `组件登记`）。也可提示作者在 Obsidian 全局搜 `#能力/xx` 人工定位。

**组件登记 \<路径\>**——入库：给指定组件文件按模板补卡（**打标必须从 `_标签.md` 词表取，缺的提议**；补**布局 ASCII 草图**，组件被改后重画）＋更新索引。组件被修改后重跑一次即可刷新卡（布局 / 参数 / 示例 / 使用方）。

**组件影响 \<组件名 | 页面名 | 路径\>**——**反向映射**：改组件或页面前反查谁在用它（业务→页面→组件 影响链的反向走法）。

1. 定位目标：按名查组件卡取「路径」，或直接给路径；给页面名则定位页面类文件——有页面卡的顺带读图例，没有的可在反查后按「模板：页面卡」补一张。
2. **代码反查为准**：全项目搜该组件 / 页面的引用（Flutter：类名 / 构造调用；iOS：类引用），组件卡「使用方」做交叉核对——代码里有、卡上没有的补进卡；卡上有、代码里没了的标废弃。命中页面的，页面卡图例「组件」列一并交叉核对（页面在用而图例没列的补进，图例有而代码没了的更新），并从图例直接读出该组件的槽位与作用，回归逐槽位过。
3. 输出**影响清单**：受影响页面 / 组件 / 模块 → 提及它们的业务文档（grep `[[页面]]` / `[[组件]]` 双链命中）→ 各模块「缺陷史」相关条目（每个使用方都要回归，有缺陷史的重点盯）。
4. 建议生成「组件 / 页面变更」需求文档（状态 `待审核`）：影响清单写进**边界**（明确波及面）与**验收标准**（每个使用方一条验收点）。
5. 变更落地交付后：重跑 `组件登记` 刷新卡，跑 `整合` 把行为变化并回各使用方的业务文档。

**组件比对 [模块|整改]**——注册表健康检测，报告闭环同「文档检查」：**比对出报告 → 按报告整改 → 改完删报告**。比对只写报告；整改只按报告修文档侧（图例、链接、使用方），**不动业务代码**。

**比对**（无参数＝全项目逐模块串行，上下文纪律同「深度拆解」；或点名模块）：按下列五项检测，发现写入报告 `docs/组件文档/_比对报告.md`（`_` 前缀＝非组件卡，不入册；每次覆盖重写），并在对话里给摘要。报告格式与整改规则同 `references/doc-check.md`：时间/范围/统计＋「待整改（AI 可修）」「需作者定夺」两组 checkbox 条目。

1. **页面覆盖**：页面目录（`presentation/pages/` 等）逐页对照——代码有页面没建卡 = **缺卡**（需作者定夺：确认后跑 `组件解析 <模块>` 建卡）；页面卡在、页面代码没了 = **孤儿卡**（需作者定夺：删或标废弃）。
2. **槽位漂移**：读页面当前实际引用的组件，对照卡上图例「组件」列——代码在用、图例没列 = **漏记**（AI 可修：按代码补图例行）；图例有、代码没了 = **过期**（AI 可修：更新图例）。
3. **链健康**：页面卡「业务」死链、或写「无」但业务文档其实提及该页面 = **业务链缺失**（AI 可修：补/改「业务」双链）；图例写文件名但组件已入册 = **待升级 `[[卡名]]`**（AI 可修）；`[[卡名]]` 目标卡不存在 = **死链**（需作者定夺：组件被删则清该槽位行，拼错则改）。
4. **织链欠账**：业务文档没有「页面 / 组件双链清单」小节、或页面双链没指向已有页面卡（仍写类名）（需作者定夺：走 `整合 <模块>` 织链，本命令不代织）。
5. **使用方核对**（顺带，仅限本次扫到的页面触达的组件）：组件卡「使用方」与代码引用对照，过期条目列入「待整改」（AI 可修：按代码更正）。

**整改**（参数＝`整改`）：读 `_比对报告.md`——报告不存在就如实说明，先跑比对；不许凭记忆整改。逐项处理「待整改」（补图例、升级卡链、更正使用方——只改文档不动代码），修一项勾一个 `[x]` 并注明已修内容；「需作者定夺」不代做。「待整改」全勾＋定夺项处理完 → **删除报告文件**；有剩余保留并汇报。

反向映射的另一路是 Obsidian 原生反链：需求 / 任务文档里的 `优先复用：[[组件名]]` 双链、业务文档里的 `[[页面名]]`，会在组件卡与页面的**反向链接面板**里全部可见。
