# /dev-review 说明书

**这是什么**：开发任务的交付审核工作流，与 Obsidian「AI Work Review」插件配合（面板顶部切到「开发模式」按任务查看）。AI 干活 → 交付单进 Obsidian → 你审 → AI 按意见继续，直到你标记通过。

## 命令用法

| 命令 | 时机 | 作用 |
|---|---|---|
| `/dev-review 需求 <任务描述>` | 开工前 | 把对话需求转写成需求档案（目标、验收标准 checkbox、边界与非目标），存入 `开发需求/` |
| `/dev-review 交付 <任务>` | 功能做完 | 对照需求自检，写交付单（改动清单、真实自测结果、验收步骤、风险）存入 `开发交付/`，状态=待审核 |
| `/dev-review 继续` | 你审完后 | 读取面板「调整」意见 + 交付单「审核意见」节，逐条落实后交回复审 |
| `/dev-review 状态` | 随时 | 列出所有任务卡在哪一步、下一步该谁动作 |
| `/dev-review:info-cn` / `:info-en` | — | 显示本说明书（中/英文） |

## 文件去向

| 位置 | 内容 | 说明 |
|---|---|---|
| `开发需求/` | 需求档案（可见） | 你可在 Obsidian 直接阅读、批注 |
| `开发交付/` | 交付单（可见） | 审核对象；状态字段被插件跟踪（待审核/修改中/已通过） |
| `.ai-review/adjustments/` | 面板「调整」写的意见 | AI 执行 `继续` 时优先读取，处理后自动清除 |
| `.ai-review/proposals/` | 文档类修改稿 | 涉及 vault 内其他文档的改动走 diff 确认 |

## 工作闭环

```
/dev-review 需求（可选）→ 开发 → /dev-review 交付
→ Obsidian 开发模式审交付单：满意点「通过」；不满意点「调整」写不足点（或写在交付单「审核意见」节）
→ /dev-review 继续 → AI 逐条落实、重新交付 → 复审 → 通过
```

## 核心规则

1. 交付单必须诚实：测试没过就写没过，未实现就写未实现——你靠它做批准决策。
2. AI 绝不直接改 vault 里开发目录之外的文档（一律走修改稿 diff）；代码改动不在此限。
3. 需求与交付按任务名自动配对（日期前缀剥离后同名），目录名可在插件设置中调整。
