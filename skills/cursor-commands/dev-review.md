第一个词是子命令：`解析模块` / `解析业务` / `深度拆解` / `需求` / `微改` / `添加` / `交付` / `整改` / `添加BUG` / `变更` / `调整` / `开工` / `继续` / `状态`，其余为参数。没有参数时执行 `状态`。

先加载并遵守技能 dev-review 的 SKILL.md：优先项目级 `.cursor/skills/dev-review/SKILL.md`（ZCode 为 `.zcode/skills/`），没有则读用户级 `~/.cursor/skills/dev-review/SKILL.md`（ZCode 为 `~/.zcode/skills/`）。若子命令是 `解析业务` 或 `深度拆解`，用同样方式再加载技能 `dev-parse-biz` 的 SKILL.md。

用户参数：$ARGUMENTS

按技能执行，不要往仓库写模板文件。开发文档固定写在 `docs/开发文档/<模块>/`。记录走 `添加`（BUG / 变更 / 补充，面板按钮的 AI 侧等价；`添加BUG` 是 `添加 BUG` 的快捷写法）；处理只认已记录的条目——记缺陷用 `添加BUG`，修缺陷用 `整改`；开工后改需求先记变更，再 `调整` 合入定稿、`变更` 落地，不许串跑。都不要新开文档。小改动没有归属文档时用 `微改` 开精简档案，别拿它当快捷通道跳过「通过」。
